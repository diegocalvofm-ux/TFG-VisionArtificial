# exp002

## Objetivo e hipótesis
Entrenar RF-DETR Nano, partiendo de los pesos COCO que trae por defecto, para localizar la lechuga (etapa 1, una sola clase: `lechuga`).

## Datos
Dataset `etapa1_v1`: svodk + giovi, sin tipburn. Según su `informe.json`, train tiene 1395 imágenes con 2807 cajas y valid tiene 39 imágenes de svodk con 553 cajas. Las 39 imágenes de valid son todas de svodk; giovi solo está en train. No hay partición de test (está vacía).

## Configuración
Entrenado el 1 de noviembre de 2026 en Google Colab con una GPU T4, rfdetr 1.11.2, 30 épocas. Los commit y las versiones de Python y PyTorch de Colab no se han registrado todavía (campos vacíos en la cabecera). El bloque siguiente es una copia del YAML de entrenamiento tal como está ahora en el repositorio.

```yaml
# Entrenamiento de RF-DETR Nano para la etapa 1 (localizar la lechuga) con el dataset etapa1_v1.
# Todos los parámetros del entrenamiento salen de aquí (el código no lleva valores fijos).
# Valores de partida: se ajustan tras el primer --smoke (tiempo por época y memoria de la GPU).

modelo:
  clase: RFDETRNano    # solo modelos Apache-2.0 (Nano, Small, Medium); XL y 2XL son rfdetr_plus (PML)
  resolucion: 384      # la del preentrenamiento del Nano; múltiplo de 32 (patch 16 x 2 ventanas)
  clases: [lechuga]    # una sola clase, la del dataset exportado

entrenamiento:
  epocas: 30           # se ajusta desde pesos COCO; valid (39 imágenes) no distingue mejoras finas
  batch_size: 8        # lote físico prudente para los 16 GB de una T4 con fp16
  grad_accum_steps: 2  # lote efectivo 8 x 2 = 16
  lr: 1.0e-4           # valores por defecto de rfdetr para un lote efectivo de 16
  lr_encoder: 1.5e-4
  amp_dtype: auto      # rfdetr elige fp16 en la T4 (sin bf16) y fp32 en CPU
  num_workers: 2
  early_stopping: false
  checkpoint_interval: 10
  tensorboard: false   # no hace falta: el metrics.csv se escribe siempre
  dispositivo: auto    # cuda si hay GPU, si no cpu

semilla: 42

datos:
  dataset: data/processed/etapa1_v1   # relativa a la raíz; la genera src.data.importar_publicos
  repeticiones_svodk: 1               # k: las imágenes de svodk aparecen k veces en train, nunca en valid
  prefijo_svodk: "svodk_"             # los nombres de archivo exportados empiezan por la fuente
  trabajo: data/processed/trabajo     # copias de trabajo <trabajo>/<exp_id>/ (fuera de runs/ y de Drive)

salida:
  carpeta: runs                       # cada ejecución va a runs/<exp_id>/

smoke:                                # --smoke: una prueba rápida de que todo funciona
  epocas: 1
  imagenes_train: 20
```

## Resultados
- Tiempo de entrenamiento: 2325,95 s (unos 38,8 min).
- Mejor época: 14 de 30.
- **AP50:95 = 0,6814** (métrica principal) y AP50 = 0,9512, sobre valid (39 imágenes de svodk).

El checkpoint elegido es `checkpoint_best_total.pth`, en `runs/exp002-etapa1-rfdert-n/pesos/` (ignorada por git).

## Análisis de errores
- **Cifra optimista.** valid se usó para elegir la época (el mejor punto se escoge con la propia métrica de valid) y no hay una partición de test independiente, así que 0,6814 no es una estimación limpia del rendimiento en datos nuevos.
- **Errata en el nombre de la carpeta.** La carpeta de la ejecución se llama `runs/exp002-etapa1-rfdert-n` (con «rfdert», por «rfdetr»). La configuración de `exp003` (`configs/eval/localizacion.yaml`) apunta a esa ruta tal cual.
- No se ha hecho análisis de errores por imagen de este entrenamiento; la comparación con otros métodos y los ejemplos están en `exp003`.

## Conclusión y siguiente paso
RF-DETR Nano alcanza AP50:95 = 0,6814 y AP50 = 0,9512 en valid, con la salvedad de que la cifra es optimista. Siguiente paso: evaluarlo en CPU frente a OWL-ViT sin entrenar y a una línea base clásica (`exp003`).
